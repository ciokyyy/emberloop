# AGENTS.md — emberloop-web/memory

## Purpose

The memory engine package `memory`: one SQLite bank per User (observations, Rules, queue, Profile versions, ledger) with FTS5 recall, append-only Rules, human purge and `VACUUM INTO` snapshots. In process, Go only, `modernc.org/sqlite`, no cgo. Design: `.scratch/web-v1/spec.md` (Data model, Retrieval and injection, Nightly job) and `docs/adr/0003-in-process-memory-engine-with-grounded-rules.md`.

## Ownership

Owns `emberloop-web/memory/`. The Daemon reaches it only through the `Memory` interface. `NewFake` is the test double for Daemon API tests. Nothing else opens bank files.

## Local Contracts

- Files: `Open(root)` returns an `Engine`; `Bank(userID)` opens `root/users/<userID>.db` on first use. Snapshots go to `root/snapshots/<userID>/<UTC stamp>.db`. A user ID must match `^[A-Za-z0-9][A-Za-z0-9_-]{0,127}$`, else `ErrInvalid`.
- Writes: each bank has one writer goroutine and one writer connection. Every write goes through `Bank.write`. Reads use a `query_only` pool. Pragmas: WAL, `busy_timeout(5000)`, `synchronous(NORMAL)`. Writer transactions begin `IMMEDIATE` (`_txlock=immediate`).
- Schema: `migrations` in `schema.go` is append-only; `PRAGMA user_version` counts them. Never edit a shipped migration; add one.
- IDs: every table uses `id INTEGER PRIMARY KEY AUTOINCREMENT`. The FTS rowid is that `id`. VACUUM renumbers rowids of tables without it, which would desync FTS.
- Never delete: `BEFORE DELETE` triggers abort every DELETE with `use purge`. `rules_guard` aborts an UPDATE that changes anything but `status`. An edit is a new version: `ReviseRule` marks the old version `superseded` in the same transaction.
- Purge is the one delete path. In one transaction it drops the abort triggers, deletes the selection, clears the purged text from `queue.payload`, `ledger.detail` and `profile_versions` (JSON fields are matched on decoded strings and keys, so the document stays valid), rebuilds both FTS indexes and recreates the triggers. Then it runs `VACUUM`, `wal_checkpoint(TRUNCATE)` and the same purge on each snapshot file, with `secure_delete` on. A failed step after the commit does not skip the rest; the errors join.
- Text: `split_text` is `SplitText(text)`: camelCase words expand to their parts, so `TestUploadHandler` also matches `upload handler`. `Query(text)` quotes each word (letters, digits and combining marks), adds camelCase parts, dedupes, caps input at 512 runes, each term at 40 and the count at 24, and joins with `OR`. No term gives an empty query, not an error. Punctuation and operators never reach FTS5.
- Heuristic miner (`miner.go`): `ClassifyHeuristic(text)` ports the claude-reflect (MIT) tables in the upstream order (slash-command guard, length floor, explicit `remember:`, guardrails, false-positive rejects, non-correction deny list, positives with 25-char floor and forward-pivot reject, strong/weak corrections with the 150-char weak gate, CJK patterns) with its confidence adjustments. Slash commands never classify, even holding `remember:` (`/remember` is ticket 18's path, not the miner's).
- Deciders (`decider.go`): `Decider` answers `durable`, `kind`, `scope_hint`, `contradicts` and `relevant` (at most 6 per call, choice options 2 to 8) with probabilities and never writes; `HeuristicDecider` is the miner pass as pass/fail (durable carries its confidence), `LLMDecider` asks a model through a caller-supplied one-off seam with redacted, size-capped state and strict JSON parsing, `EnsembleDecider` proposes with the first and confirms with the second against `confirmLow`/`confirmHigh` (defaults 0.35/0.7; drop, observe, eligible), `UnavailableDecider` never answers (the unconfigured ensemble second), and `ScriptedDecider` is the test fake. `JevDecider` (`jev.go`) POSTs the shared `model`/`state`/`questions` body to the configured endpoint URL verbatim (hosted `/api/v1/decisions`, TypeSafe `/v1/systemone`, or local laya-serve `/v1/systemone`), so Laya plugs in by URL with no adapter: unknown reply fields are ignored. Noul, choice and score answers parse into the result (score normalises to `score/(levels-1)`); limits are enforced before anything is sent, the state is redacted with `ForJev` and size-capped in the same function as the send, an empty URL never sends, and every transport, status or shape failure is `ErrDeciderUnavailable`. Laya verified against the upstream README and laya 0.4.2 `serve.py`: `/v1/systemone` only, schema-identical contracted keys, extras ignored, `model` honours checkpoint names (`jev-*` routes), `confidence` is not Jev's formula so callers gate on probability. Invalid or out-of-range output is `ErrDeciderUnavailable`, never a yes; malformed JSON fails the call while one bad answer silences only itself.
- Eval (`eval.go`, ticket 30): pure offline metrics. `CoversRule` is the dedup `Relation` as coverage (contradictions count); `RecallAt5`/`RepeatRate` share covered-over-total (empty is 0); `TopCovered` caps at 5; `HeuristicScore` is the live confidence or 0. Labels are JSONL (`ParseDeciderLabels`: id and text required, kind validated, duplicates rejected); decided queue rows map via `QueueItemLabels` (approved durable, rejected not, pending unjudged and skipped, textless skipped). `ParseDeciderScores` validates 0-to-1 probabilities; `ScoreDecider`/`ScoreEvalDeciders` report precision and recall at the approve threshold for `heuristic` (live), `llm`, `jev`, `laya` (missing unscored). `ScoreEvalCases` reports FTS recall, embedder recall and the gap on the same hit lists. Cases live in `eval_test.go`.
- Cursor (`cursor.go`): `Cursor{offset, size, headHash}` per `events.jsonl`; `ReadNew` returns bytes after the offset up to the last newline, so a torn line waits. A changed head prefix or a shrunk file resets with `reset=true`; pure appends never reset. `LoadCursor` treats missing/corrupt as zero; `SaveCursor` writes atomically.
- Dedup (`dedup.go`): `NormalizeQuote` drops filler stopwords but keeps every negation token and polarity adverb. `Relation` assigns duplicate (equal), contradicts (overlapping substance, opposite polarity via negation difference or always/never-type antonyms) or refines (containment or Jaccard >= 0.5), else none. `DedupAndStore` replays the same Session Event without bumping, bumps a duplicate's `evidence_count` via `BumpObservationEvidence` (count-only UPDATE, FTS untouched), and inserts refines/contradicts/novel with the relation and the related row recorded in `decider_json` for the queue stage; nothing is dropped.
- Grounding: `CheckGrounding` in `ground.go` takes a `GroundEvent` (found, sender, text tied to one Event, so a wrong join cannot pass silently) and verifies a candidate quote (exists, `sender=user`, verbatim substring) without a model; anything else is `ErrNotFound` or `ErrInvalid`. The miner calls it before an observation reaches the bank, on already-redacted text.
- Redaction: `Redact` in `redact.go` ports the deja-vu (MIT) secret patterns (cloud keys, provider tokens, JWTs, connection URLs, `Bearer`/`Basic`, CLI password flags, multilingual key-value forms, PEM blocks whole and truncated) with `[redacted:<kind>]` markers. It is the only path to the distill LLM, a Decider LLM and the Jev client through `ForDistill`, `ForDecider`, `ForJev` (`RedactedFor`). Golden cases live in `redact_test.go`, grounding in `ground_test.go`. `egress_test.go` walks every Go file of the module and parses each function: one that names an egress role (or lives in an egress package) and sends without calling the redactor in the same function fails, as does an unparsable file; comments never count and a guard in one function never silences another. Synthetic cases pin the failure modes.
- Recall: live rows only, through an `EXISTS` filter (status not `superseded` or `dormant`), at most 20 (`MaxRecall`). `parked` Rules stay live for manual `recall`; auto-injection skips them.
- Profile (`profile.go`): lines with stable IDs (`l1`, `l2`, ...) in `profile_versions`; ops add, edit, retire by line ID. `GetProfile` returns v0 empty; `AppendProfileVersion` validates, refuses an over-2 KB render with a condense message and stores the next version; `RestoreProfileVersion` copies an old version as new. `RenderProfile` joins live lines; `RenderReviewerProfile` keeps workflow and style only, never barred lines (heuristic expertise and review-bar phrases must stay `other`). A retire hides, never deletes. The cap lives in one helper (`checkProfileBytes`/`checkProfileCap`) shared by the renderer, the bank and the fake; bank Append and Restore share `loadProfileRows`/`insertProfileRow` (fake: `insertProfileVersionLocked`).
- Snapshots: `Snapshot` runs `VACUUM INTO` unless the newest snapshot is under 6 hours old (`SnapshotInterval`). It keeps the newest 10 (`SnapshotKeep`). File names carry the time, so order comes from names.
- Anchors (`anchors.go`): `ExtractAnchors(quote, toolTexts, goMod)` is deterministic (sorted, deduped, capped at `MaxAnchors=20`, each at most `MaxAnchorRunes=200`); it finds slash paths, bare source files and explicit `module@version`, and resolves packages against `go.mod` requires. `NormalizeAnchors(kind, anchors)` drops preferences to nil. `validRule` refuses only preference Rules with anchors and empty/whitespace anchors (same rule as `cleanAnchor`); the spec caps only Rule text, so anchor count and length stay extraction caps, never write limits.
- Verification (`anchors.go`): `VerifyRule(ctx, workDir, rule)` runs `git diff --name-status <observed_commit>..HEAD -- <paths>` in the worktree (machine-readable form of the spec's `--stat`; slash-less anchors add a `**/` pathspec so bare files match subdirectories). Clean injects as-is; changed injects with `FlagNote()` ("code changed since <date>, verify", committer date). A path anchor goes dormant only when its path is gone at HEAD (`HEAD:<anchor>`); a file deleted under a directory anchor is a change, not a dormant directory. Each `module@version` is compared to HEAD's `go.mod`: missing module is dormant, moved version is changed, unrelated edits stay clean. Missing commit, non-ancestor, non-repo, outside-worktree anchor or any git failure returns stale, which flags instead of failing the turn. Preferences, anchorless and commitless Rules are clean without git. `VerifyRules` keeps order; `ApplyVerification` runs it and marks dormant Rules via `SetRuleStatus` for injection (ticket 24) and the nightly check.
- Notes (`notes.go`, library-only): project notes are Markdown files with frontmatter (`id`, `anchors`, `observed_commit`, `author`, `subject_key`) in `.emberloop/notes/`, branch-aware per worktree. `LoadNotes(workDir)` resolves the notes dir through the worktree toplevel and skips malformed files and duplicate ids with notices, never an error. `OpenNotesIndex(notes)` builds the temporary per-worktree FTS5 index (in-memory SQLite, same `Query`/`SplitText` rules as bank recall). `VerifyNote` reuses `VerifyRule` as a non-preference Rule: deleted anchors verify dormant and `RecallNotes` skips them, changed and stale keep the flag. `FuseRecall` merges ranked Rules and notes by reciprocal rank fusion (k=60); BM25 scores never cross tables, ties break Rules first, then by id. The Daemon consumes `RecallNotes`/`FuseRecall` in auto-recall injection (`../recall_inject.go`, ticket 24). The package only reads; nothing writes or commits.
- Fake: `fake.go` keeps the same rules (validation, live filter, purge scrub, snapshot policy, Profile cap and filter, evidence bump) and matches by term count, not FTS5 rank. Every `Memory` method needs a case in `contract_test.go`, which runs against the bank and the fake; Profile cases live in `profile_test.go`.
- Notice: `schema.go` adapts mnemopi (MIT), `redact.go` ports deja-vu (MIT) and `miner.go` ports claude-reflect (MIT). `NOTICE.md` holds all three notices. Keep them when the schema or the patterns change.

## Verification

In `emberloop-web/`: `go vet ./memory/ && go test ./memory/`. The repo check runs `go test ./...` there. Trigger, FTS integrity (`integrity-check`), purge file-bytes and concurrency tests live in `bank_test.go`, `purge_test.go` and `snapshot_test.go`; grounding, redaction goldens and the egress-guard scan in `ground_test.go`, `redact_test.go` and `egress_test.go`. Heuristic goldens, cursor reset/torn-line and dedup relations with the bump live in `miner_test.go`, `cursor_test.go` and `dedup_test.go`. Decider validation, heuristic answers, LLM parsing with redaction, ensemble thresholds and the scripted fake live in `decider_test.go`. Jev answer parsing (noul, choice, score), error mapping, client-side limits, redaction and caps, and Laya-shape compat live in `jev_test.go`. Eval coverage, labels, scores and precision live in `eval_test.go`. Anchor extraction tests live in `anchors_test.go`; temp-git-repo verification (clean, changed with flag, deleted to dormant, foreign branch, missing commit, preferences, bare files, directory semantics, precise modules, outside/cancelled stale, `ApplyVerification`) lives in `verify_test.go` and `verify_review_test.go`. Project-notes branch-awareness across two worktrees, deleted-anchor skip, malformed-file notices, rank-fusion merge and frontmatter forms live in `notes_test.go`.
