# AGENTS.md — emberloop-web/memory

## Purpose

The memory engine package `memory`: one SQLite bank per User (observations, Rules, queue, Profile versions, ledger, Memories and Episodes) with FTS5 recall, append-only Rules, human purge and `VACUUM INTO` snapshots. Redacted OpenRouter embeddings are computed by a bounded async worker; vectors use little-endian float32, model-isolated cosine ranking is capped at 50,000 rows and 800 ms, with FTS fallback and a 256-entry query LRU. In process, Go only, `modernc.org/sqlite`, no cgo. Design: `.scratch/web-v1/spec.md` and `.scratch/memory-v2/spec.md`.

## Ownership

Owns `emberloop-web/memory/`. The Daemon reaches it only through the `Memory` interface. `NewFake` is the test double for Daemon API tests. Nothing else opens bank files.

## Local Contracts

- Files: `Open(root)` returns an `Engine`; `Bank(userID)` opens `root/users/<userID>.db` on first use. Snapshots go to `root/snapshots/<userID>/<UTC stamp>.db`. A user ID must match `^[A-Za-z0-9][A-Za-z0-9_-]{0,127}$`, else `ErrInvalid`.
- Writes: each bank has one writer goroutine and one writer connection. Every write goes through `Bank.write`. Reads use a `query_only` pool. Pragmas: WAL, `busy_timeout(5000)`, `synchronous(NORMAL)`. Writer transactions begin `IMMEDIATE` (`_txlock=immediate`).
- Schema: `migrations` in `schema.go` is append-only; `PRAGMA user_version` counts them. Never edit a shipped migration; add one. Migration 3 adds `memories` and `episodes`, their FTS and triggers, the `memories` update guard, and no-delete triggers.
- IDs: every table uses `id INTEGER PRIMARY KEY AUTOINCREMENT`. The FTS rowid is that `id`. VACUUM renumbers rowids of tables without it, which would desync FTS.
- Never delete: `BEFORE DELETE` triggers abort every DELETE with `use purge`. `rules_guard` aborts an UPDATE that changes anything but `status` and the promotion columns (`promoted_at`, `promoted_by`); migration 2 recreates it with that allowance. An edit is a new version: `ReviseRule` marks the old version `superseded` in the same transaction. New Rules start unpromoted; `AddRule`, `ReviseRule` and `ApproveRule` clear the promoted columns.
- Spec deviation (spec.md Data model): the spec's rules row lists no promotion marker and its triggers paragraph allows `rules` updates only for `status`. Promotion stamping needs a marker that survives without changing status or provenance, so migration 2 adds `promoted_at`/`promoted_by` and the guard allows those two columns alongside `status`. Purge already scrubs promotion payloads as queue JSON. Recorded here as the deviation's home.
- Promotion (`promote.go`): `PromotionProposal` is the JSON of a kind=promotion queue item (Rule, Session worktree, target `agents_md` or `note`, repo-relative target path, diff preview, provenance). `NearestAgentsMD` walks up from the workDir to the git toplevel for the nearest `AGENTS.override.md`/`AGENTS.md`/`AGENTS.MD`, proposing a new toplevel `AGENTS.md` when none exists. `BuildAgentsMDEdit`/`AgentsMDDiff` append one `- <text>` bullet with a unified preview, idempotent on the exact bullet line (a shorter Rule beside a longer line still appends). `NotesTargetPath` maps a Rule to `.emberloop/notes/<id>.md`; `FormatNoteFile` renders frontmatter (`id`, `anchors`, `observed_commit`, `author`, `subject_key`) that `ParseNote` reads. `VerifyPromotionTarget` keeps writes inside the worktree. `MarkRulePromoted` stamps every version (`promoted_at/by`) with status and provenance untouched; unknown IDs are `ErrNotFound`. Cases live in `promote_test.go` (nearest, fallback, override, diff, idempotency, substring collision, note parse, target guard, payload validation, stamping on bank and fake, guard refusal, migration version), reusing `verify_test.go`'s temp-git helpers.
- Purge is the one delete path. In one transaction it drops the abort triggers, deletes the selection from observations, Rules, Memories, Episodes, queue and ledger, clears purged text from `queue.payload`, `ledger.detail` and Profile versions, rebuilds all four FTS indexes and recreates the triggers. Then it runs `VACUUM`, `wal_checkpoint(TRUNCATE)` and the same purge on each snapshot file, with `secure_delete` on. A failed step after the commit does not skip the rest; the errors join.
- Text: `split_text` is `SplitText(text)`: camelCase words expand to their parts, so `TestUploadHandler` also matches `upload handler`. `Query(text)` quotes each word (letters, digits and combining marks), adds camelCase parts, dedupes, caps input at 512 runes, each term at 40 and the count at 24, and joins with `OR`. No term gives an empty query, not an error. Punctuation and operators never reach FTS5.
- Heuristic miner (`miner.go`): `ClassifyHeuristic(text)` ports the claude-reflect (MIT) tables in the upstream order (slash-command guard, length floor, explicit `remember:`, guardrails, false-positive rejects, non-correction deny list, positives with 25-char floor and forward-pivot reject, strong/weak corrections with the 150-char weak gate, CJK patterns) with its confidence adjustments. Slash commands never classify, even holding `remember:` (`/remember` is ticket 18's path, not the miner's).
- Extractor (`extractor.go`): prompt `x1`, OpenRouter chat completion, `ScriptedExtractor`, bounded retry for 429/timeouts, redacted numbered Events, quote/kind/length/redaction validation, importance assignment and heuristic fallback only after configured extraction fails. OpenRouter requests usage metadata; `CostUSD` exposes the provider-reported charge to the ingest ledger. `TestLiveExtract` uses `testdata/extract_eval.json` and is gated by `EL_LIVE_EXTRACT=1` plus `OPENROUTER_API_KEY`.
- Turn-end ingestion (`emberloop-web/ingest.go`, `mine_live.go`): idle triggers debounce 3 seconds, one scan per Session uses the same cursor, keeps only redacted user prompt/steer/follow-up Events (4 KB each, newest-first up to 15 KB), writes one Episode per kept Event and records ingest counts/model/latency/cost in the sender's bank. Validated extracted and fallback items use `DedupAndStoreMemory`; extraction receives redacted assistant context only, failures still ledger and Episodes are retained. The work is off-turn and never blocks the Session.
- Deciders (`decider.go`): `Decider` answers `durable`, `kind`, `scope_hint`, `contradicts` and `relevant` (at most 6 per call, choice options 2 to 8) with probabilities and never writes; `HeuristicDecider` is the miner pass as pass/fail (durable carries its confidence), `LLMDecider` asks a model through a caller-supplied one-off seam with redacted, size-capped state and strict JSON parsing, `EnsembleDecider` proposes with the first and confirms with the second against `confirmLow`/`confirmHigh` (defaults 0.35/0.7; drop, observe, eligible), `UnavailableDecider` never answers (the unconfigured ensemble second), and `ScriptedDecider` is the test fake. `SubjectKeyProposer` names the subject key (heuristic, LLM with redacted JSON reply, ensemble prefers the confirming second, scripted; empty or invalid is unavailable and the caller falls back to the heuristic). `JevDecider` (`jev.go`) POSTs the shared `model`/`state`/`questions` body to the configured endpoint URL verbatim (hosted `/api/v1/decisions`, TypeSafe `/v1/systemone`, or local laya-serve `/v1/systemone`), so Laya plugs in by URL with no adapter: unknown reply fields are ignored. Noul, choice and score answers parse into the result (score normalises to `score/(levels-1)`); limits are enforced before anything is sent, the state is redacted with `ForJev` and size-capped in the same function as the send, an empty URL never sends, and every transport, status or shape failure is `ErrDeciderUnavailable`. Laya verified against the upstream README and laya 0.4.2 `serve.py`: `/v1/systemone` only, schema-identical contracted keys, extras ignored, `model` honours checkpoint names (`jev-*` routes), `confidence` is not Jev's formula so callers gate on probability. Invalid or out-of-range output is `ErrDeciderUnavailable`, never a yes; malformed JSON fails the call while one bad answer silences only itself.
- Cursor (`cursor.go`): `Cursor{offset, size, headHash}` per `events.jsonl`; `ReadNew` returns bytes after the offset up to the last newline, so a torn line waits. A changed head prefix or a shrunk file resets with `reset=true`; pure appends never reset. `LoadCursor` treats missing/corrupt as zero; `SaveCursor` writes atomically.
- Memory dedup (`dedup_memory.go`): extracted items enter through `DedupAndStoreMemory`, which compares active same-bank rows before insertion, prioritizes exact normalized text, and uses compatible-model cosine thresholds when the candidate and stored vectors are available. Duplicate bumps and same-author contradiction supersession are atomic with insertion. With null vectors, only normalized text and `Relation` checks run; embedding remains asynchronous after storage.
- Queue (`queue.go`): subject keys are normalized (`NormalizeSubjectKey`: lowercase, non-alnum to dots, 64 runes) and proposed by the Decider with the heuristic `ProposeSubjectKey` as fallback (first three topic tokens, polarity dropped so opposites share a key). A candidate promotes only on recurrence across Sessions (`ShouldPromote`: two Sessions stand in for two tasks, plus a non-negative generalizing score); the approver sees one unclipped generalization (`ProposeGeneralization`) with its quotes. `PartitionSubjectRules` splits same-key live Rules by resolved observer identity (unknown or mixed never matches); `PairCandidate` reads deterministically by rule ID. `ApproveRule` approves one pending kind=rule item atomically (create, supersede, decide in one transaction; over-long text refuses with nothing changed). `AnnotateQueueRelation` writes contradiction pairing back onto a pending kind=rule payload (relation plus related Rule, decided items refuse as labels). `ObservationByID` serves author and date resolution; `ObservationsBySubjectKey` and `RulesBySubjectKey` serve promotion and supersession; all normalize on write. `DescribeQueue` reports budget (`QueueBudget=50`), size and approval latency; rejected items stay as labels and the Daemon records each mutation as a `queue_*` ledger row. Cases live in `queue_test.go` against the bank and the fake, including proposer answers, partition order, no-clip proposals, atomic refusal and the lookups; annotation cases live in `annotate_test.go` against both.
- Grounding: `CheckGrounding` in `ground.go` takes a `GroundEvent` (found, sender, text tied to one Event, so a wrong join cannot pass silently) and verifies a candidate quote (exists, `sender=user`, verbatim substring) without a model; anything else is `ErrNotFound` or `ErrInvalid`. The miner calls it before an observation reaches the bank, on already-redacted text.
- Recall: Rules stay live-only, through an `EXISTS` filter (not `superseded` or `dormant`), at most 20 (`MaxRecall`). `RecallMemories` searches Memory text and quote; it omits superseded by default and admits them only on explicit opt-in, never including forgotten or parked rows. The Session recall tool exposes `include_superseded`; injection stays separate. `LiveRules` returns the latest live version per rule ID for nightly anchor checks. Memory page lists are newest-first and capped at `MaxList`; `clampList` caps lists like `clampLimit` caps search.
- Profile (`profile.go`): lines with stable IDs (`l1`, `l2`, ...) in `profile_versions`; ops add, edit, retire by line ID. `GetProfile` returns v0 empty; `AppendProfileVersion` validates, refuses an over-2 KB render with a condense message and stores the next version; `RestoreProfileVersion` copies an old version as new. `RenderProfile` joins live lines; `RenderReviewerProfile` keeps workflow and style only, never barred lines (heuristic expertise and review-bar phrases must stay `other`). A retire hides, never deletes. The cap lives in one helper (`checkProfileBytes`/`checkProfileCap`) shared by the renderer, the bank and the fake; bank Append and Restore share `loadProfileRows`/`insertProfileRow` (fake: `insertProfileVersionLocked`). The nightly profile stage sends `{"ops":[]}` as none when no stable signal exists.
- Snapshots: `Snapshot` runs `VACUUM INTO` unless the newest snapshot is under 6 hours old (`SnapshotInterval`). It keeps the newest 10 (`SnapshotKeep`). File names carry the time, so order comes from names.
- Anchors (`anchors.go`): `ExtractAnchors(quote, toolTexts, goMod)` is deterministic (sorted, deduped, capped at `MaxAnchors=20`, each at most `MaxAnchorRunes=200`); it finds slash paths, bare source files and explicit `module@version`, and resolves packages against `go.mod` requires. `NormalizeAnchors(kind, anchors)` drops preferences to nil. `validRule` refuses only preference Rules with anchors and empty/whitespace anchors (same rule as `cleanAnchor`); the spec caps only Rule text, so anchor count and length stay extraction caps, never write limits.
- Fake: `fake.go` keeps the same rules (validation, live filter, purge scrub, snapshot policy, Profile cap and filter, evidence bump, subject-key normalization and lookup, atomic approve, queue annotation) and matches by term count, not FTS5 rank. Every `Memory` method has a case in `contract_test.go`, which runs against the bank and the fake; `LiveRules` ordering and the live filter have their case in `live_test.go` against both, annotation in `annotate_test.go` against both; deeper queue flows (proposers, partition, atomic refusal, stats) live in `queue_test.go`, Profile cases in `profile_test.go`.
- Embeddings: each Daemon's `Engine` owns one bounded worker configured by `memory_embedding_model` (default `qwen/qwen3-embedding-4b`; empty disables it) and the OpenRouter key. `Engine.SetEmbedding` swaps worker and query settings for open and future banks when admin settings are saved; bank reads and enqueue use a synchronized config snapshot. Successful `AddMemory`/`AddEpisode` commits enqueue redacted work; persisted float32 vectors include their model. Worker shutdown joins its active job and records queued skips before banks close; embed, store and queue failures append `FAILED` embedding ledger rows. The 32-item OpenRouter client, FakeEmbedder, 50,000-row model-filtered cosine search, shared 800ms vector/FTS fallback budget and 256-entry query LRU live in `embedder.go`. `ForEmbedder` is mandatory at egress. Tests: `embedder_test.go`, `dedup_memory_test.go`, `profile_test.go`.
- Notice: `schema.go` adapts mnemopi (MIT), `redact.go` ports deja-vu (MIT) and `miner.go` ports claude-reflect (MIT). `NOTICE.md` holds all three notices. Keep them when the schema or the patterns change.

- Memory dedup (`dedup_memory.go`): extracted items enter through `DedupAndStoreMemory`, which compares active same-bank rows before insertion, prioritizes normalized-text duplicates, and uses model-matched vectors when available. Duplicate bumps and same-author contradiction supersession are atomic; null vectors use normalized text and `Relation` only, while embedding stays asynchronous. Tests cover text/vector thresholds, duplicate bumps and same-/cross-author supersession.
- Hybrid recall (`hybrid.go`) unions per-table FTS top 40 and same-model vector top 40, renormalizes missing-vector weights, applies kind/veracity decay and excludes non-active Memories. Rules, notes and Memories are merged by rank, never cross-table BM25 values; Episodes use the same hybrid ranking for the recall tool only. Injection is Profile plus at most five Rules and five Memories, seven recalled items total and a 700-token budget; injection Events distinguish Rule versions and Memory IDs. Coverage: `hybrid_test.go`, `replay_test.go`, `injection_test.go`. Host-global extraction, embedding, automatic-extraction and recall-weight controls live in admin-only `/api/settings`; extraction defaults to OpenRouter-key presence and settings apply without Daemon restart.
- `RecallMemoryItems` omits superseded rows by default and admits them only on explicit opt-in; the Session recall tool exposes `include_superseded`. Coverage: `recall_memory_test.go`.
- Memory page API (`memory_page.go`): authenticated per-User endpoints list/filter Memories newest-first, count all Memories since a visit timestamp, soft-forget/park/pin, create a pending Rule queue item with supported `RuleProposal` quote/session/author fields plus `source_memory_ids` and importance, transactionally create a superseding Memory without mutating old text, promote a Legacy observation's stored candidate text/kind (falling back to its quote when no candidate text exists), and list read-only Episodes. The browser `/memory` page stores a last-visit timestamp per browser and User only after initial reads succeed, displays the unbounded new-since-visit count and queue age, and exposes the three tabs. `memory_page_test.go`, `contract_test.go` and `web/src/lib/MemoryPage.test.js` cover these behaviors.
